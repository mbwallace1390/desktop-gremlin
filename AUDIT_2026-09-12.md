## Confirmed findings

1. **Icon movement can exceed the saved layout's coverage.** Adding an icon
   after the backup allows it to move even though Restore has no saved position
   for it. Require coverage before movement and reject ambiguous identity or
   failed reads. Never replace a protected backup with an already-moved layout.
2. **Failed window restores discard their undo positions.** A failed restore
   empties the undo map, so trying again cannot recover the window. Keep failed
   live-window entries and report that restoration is incomplete.
3. **Failed cursor reads invent a position and velocity.** An unsuccessful
   Windows cursor query replaces the previous position with `(0, 0)`, creating
   an artificial high-speed movement. Ignore failed samples.
4. **Hiding the overlay leaves an active gremlin drag running.** If the mouse
   release occurs while hidden, the fighter can remain grabbed on return.
   End the app's drag state through its normal release path before hiding.
5. **Fast falls choose the first listed ledge instead of the first crossed.**
   A fall through a window top and a lower icon in one simulation step lands on
   the icon because icons are enumerated first. Resolve the nearer landing.
6. **A delayed projectile can take over its owner's newer activity.** Finishing
   a target with an old shot can change a knocked-out, grabbed, or sleeping
   fighter to idle, or cancel a newer target. Keep impact handling separate
   from permission to finish the owner's current activity.
7. **Applying settings silently shortens a valid idle preference.** Saved
   values up to 120 minutes are supported, but the form clamps them to 60.
   Match the slider to the supported range. A saved 90-minute preference now
   survives opening Settings and applying a different visual preference.
8. **Blasts mix up cached icon labels.** The list of nearby icons drops each
   name, then movement reuses the last name from the scan for every moved icon.
   Carry each icon's own label through the movement update.

## Verification boundaries

No real desktop icons or application windows are moved by these tests. Native
rendering remains quarantined after the input-lockout incident. Drag-state
checks exercise application state and withdrawal ordering; they do not claim
to prove Windows mouse-event delivery or desktop-wide click-through.

Negative desktop-origin geometry was checked using an owned withdrawn Tk
window and accepted by Tk; it was not a bug and was left unchanged. A possible
pending-batch restore race was not reproduced through the actual callback
ordering and was not changed speculatively.

## Completed repairs and verification

All eight findings above are addressed. Regression checks were run and observed
failing before the corresponding code changes, then passing afterward. The new
`test_desktop_recovery.py` and `test_behavior_recovery.py` suites are registered
in the runner; existing input, settings, icon, and shell tests were extended.
An older runtime test's fake ListView was corrected to model the new identity
lookup while preserving its dirty-before-write assertion.

Final Windows verification with the existing local Python 3.14 environment:

```powershell
.\.venv\Scripts\python.exe -B tests\run_all.py
```

**30/30 suites passed in 15 seconds.** All nine changed Python files also parse
with Python 3.8 syntax rules; this is not a separate Python 3.8 runtime test.
Independent reviews found no blocking issues in either the gameplay/input
changes or the shell recovery protocol. The latter also passed a separate
byte-accurate fake-memory probe.

The icon lookup follows Microsoft's documented [LVM_FINDITEM behavior](https://learn.microsoft.com/en-us/windows/win32/controls/lvm-finditem)
and [LVFINDINFOW layout](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/ns-commctrl-lvfindinfow).
Each normal movement uses one name read, two exact searches, and the position
write. Tests cover duplicate and missing labels, changing indices, failed
reads, and failure replies. Real Explorer latency and simultaneous external
inventory changes were not tested.

Before/after fingerprints confirm that the actual settings, icon backup,
memory, log, and tray-icon files were unchanged during this audit. No commit
or push was made. Relaunch Desktop Gremlin to load the repaired code.
